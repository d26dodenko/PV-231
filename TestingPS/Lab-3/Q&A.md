# Контрольные вопросы к лабораторной работе №3

## 1. Что такое пирамида тестирования и почему она важна?

Это распределение тестов по уровням. В основании много быстрых и изолированных unit-тестов. Выше находятся тесты взаимодействия компонентов, а на вершине несколько сквозных сценариев. Такое распределение ускоряет обратную связь и облегчает поиск причины падения.

## 2. Какие паттерны автоматизации UI вы знаете?

Page Object хранит локаторы и действия страницы в одном классе. Component Object применяет тот же подход к повторяемым компонентам, например меню. Fixtures подготавливают состояние, например чистый контекст браузера или отдельную учётную запись. Тесты с параметрами используют один сценарий с разными входными данными.

## 3. Что такое quality gates и зачем они нужны?

Quality gate — обязательное условие, которое проверяется автоматически. Например, сборка продолжается, когда проходят тесты, покрытие соответствует порогу и аудит не обнаруживает критических предупреждений. Защита ветки применяет результаты этих проверок при слиянии PR.

## 4. Почему unit-тесты запускаются на каждый коммит, integration — после сборки, а E2E — перед релизом?

Unit-тесты дают быструю обратную связь после push или обновления PR. Интеграционные тесты требуют подготовленного приложения и зависимостей. E2E проверяют пользовательский путь на работающем стенде и стоят дороже по времени. В этом workflow среду для integration и E2E поднимают заранее, а сборка релизного артефакта начинается после обеих проверок.
