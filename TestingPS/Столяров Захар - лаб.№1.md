## 2. Анализ исходного кода

В Bonus Storm у `WILD` особое правило: он заменяет обычный символ в серии. При бесплатном вращении номинальная ставка участвует в расчёте выигрыша, а сумма операции со ставкой равна нулю. Эти два сценария проверяются отдельно, как скидка и бесплатная доставка в примере задания.

| Файл | Объект проверки |
| --- | --- |
| `apps/games/forms.py` | `SlotBetForm` проверяет введённую ставку. |
| `apps/games/views.py` | `_line_payout` рассчитывает выигрыш по одной линии, `_scatter_triggered` определяет наличие бонусной комбинации, `slot_bonus` обрабатывает вращение. |
| `apps/games/slot_bonus_config.py` | `PAYTABLE` задаёт множители, `PAYLINES_20` — линии, `SCATTER_REELS` — нужные барабаны, `FREE_SPINS_AWARD` — размер бонуса. |

### Бизнес-правила

| ID | Правило |
| --- | --- |
| BR-01 | Ставка обязательна. Допустимы числа от 2 до 100 000 включительно, максимум с двумя знаками после десятичного разделителя и общим лимитом в 14 цифр по настройке поля. При успешной проверке ставка доступна как `Decimal`. |
| BR-02 | Линия состоит из пяти символов. Серия считается с первого барабана и завершается при первом несовпадении. Менее трёх совпадений дают результат `(Decimal("0"), None, 0)`. |
| BR-03 | Базовым считается первый символ, отличный от `WILD`. `WILD` засчитывается в серию вместо базового символа. У линии из пяти `WILD` базовый символ — `WILD`, множитель — 140. |
| BR-04 | `SCATTER` среди первых трёх символов исключает линейную выплату. `SCATTER` после трёх совпавших обычных символов может завершить серию, сохранив уже набранные совпадения. |
| BR-05 | Для серии из трёх, четырёх или пяти совпадений ставка умножается на коэффициент из `PAYTABLE`. Выигрыш округляется до сотых через `Decimal.quantize`. При стандартном контексте точная половина округляется к ближайшей чётной цифре. При отсутствии положительного коэффициента выплата равна нулю. |
| BR-06 | Для бонусной комбинации требуется хотя бы один `SCATTER` в любой строке каждого из барабанов 1, 3 и 5. В коде их индексы — 0, 2 и 4. Несколько символов на одном барабане не заменяют символ на другом. |
| BR-07 | Платное вращение вызывает списание ставки и при бонусной комбинации добавляет 10 бесплатных вращений. Без бонусной комбинации счётчик не пополняется. |
| BR-08 | При положительном остатке вращение бесплатное. Счётчик уменьшается на единицу, обычное списание не вызывается, в журнал передаётся операция на сумму 0 с номинальной ставкой в метаданных. В бесплатном режиме бонус повторно не начисляется. |
| BR-09 | Обработчик рассчитывает выплаты по всем 20 линиям и суммирует положительные результаты. При положительной итоговой сумме обработчик передаёт её и сведения о линиях в функцию начисления выигрыша. |

### Входы, выходы и ограничения

| Объект | Входы | Выходы |
| --- | --- | --- |
| `SlotBetForm` | Поле `bet` с текстом ставки из формы. | Признак валидности, нормализованное значение `Decimal` или код ошибки поля. |
| `_line_payout` | Последовательность из пяти идентификаторов символов слева направо и ставка `bet` типа `Decimal`. | Кортеж `(выигрыш, базовый символ, длина серии)`. |
| `_scatter_triggered` | Поле из пяти барабанов по три позиции на каждом. | `True` или `False` для бонусной комбинации. |
| `slot_bonus` | POST-запрос авторизованного игрока со ставкой, остаток бесплатных вращений и игровое поле. | Данные для страницы, включая режим, остаток, число начисленных вращений, выигрыш и оплаченные линии. Обработчик также вызывает операции со ставкой, сессией и выигрышем. |

Допустимые символы линии — `LOW1`, `LOW2`, `MID1`–`MID3`, `HIGH1`–`HIGH3`, `WILD` и `SCATTER`. В штатном потоке их поставляет генератор игрового поля. Неизвестный код символа находится вне допустимого алфавита. Для неизвестной базы с серией из трёх элементов проверяется защитная ветвь без выплаты.

#### Классы эквивалентности и границы

- Ставка ниже диапазона, внутри диапазона и выше диапазона. Проверены `1.99 / 2.00` и `100000.00 / 100000.01`. Для ставки также выделены классы с лишним десятичным знаком, нечисловым и пустым вводом.
- Серия короче трёх символов либо длиной 3, 4 или 5. Граница появления выплаты проверяется на двух и трёх совпадениях. Отдельно проверяются подстановка `WILD`, отсутствие коэффициента и `SCATTER` на позициях 3 и 4.
- Все три требуемых барабана содержат `SCATTER`, только два содержат `SCATTER` или хотя бы один из трёх символов размещён на неподходящем барабане.
- Остаток вращений равен 0 или положителен. Граница между платным и бесплатным режимами проверяется значениями 0 и 1.

## 3. Тест-кейсы

Шаги для каждой группы тестов

- **Форма.** Передать ставку в `SlotBetForm` и вызвать `is_valid()`. Проверить принятую ставку или код ошибки.
- **Линия.** Передать символы и ставку в `_line_payout`. Сравнить сумму, символ и длину серии с ожидаемыми.
- **Бонусная комбинация.** Расставить `SCATTER` на поле 5 × 3 и вызвать `_scatter_triggered`.
- **Вращение.** Создать тестового игрока с балансом 200 и заданным остатком вращений. Подставить поле и передать в `slot_bonus` POST со ставкой 5.00. Проверить результат и суммы в вызовах списания и начисления. Операции с данными заменены тестовыми объектами.

## 4. Автотесты и запуск

В [test_bonus_storm.py](code/test_bonus_storm.py) каждому кейсу соответствует параметризация с тем же ID. Проверяются значения `Decimal`, коды ошибок Django и вызовы операций в обработчике. Фиксированные игровые поля делают результаты повторяемыми. [conftest.py](code/conftest.py) загружает исходный код курсового в изолированном тестовом окружении. Для запуска нужна локальная копия курсового проекта Casino, Python 3.12 или новее, Django и pytest. Подключение к PostgreSQL не требуется.

Из папки `TestingPS` в PowerShell. В последней команде укажите свой путь к каталогу курсового проекта, где лежит `manage.py`.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install Django==6.1.3 pytest==9.2.0
.\.venv\Scripts\pytest.exe -v code --casino-project='D:\projects\casino'
```

**Оставшиеся риски.** Тесты используют заранее заданные поля, поэтому распределение случайных символов осталось без проверки. Отдельные коэффициенты и координаты линий тоже могут содержать ошибки. На этапе анализа тесты помогают уточнить правила. Например, ставка ровно 2.00 должна приниматься, а 1.99 отклоняться. Во время разработки такая пара проверок помогает поймать ошибку на границе. После изменений можно запустить тесты снова и убедиться, что за бесплатное вращение по-прежнему не списывается ставка.
